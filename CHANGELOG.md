# Changelog

Все заметные изменения проекта фиксируются в этом файле.

Формат — по мотивам [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — по [Semantic Versioning](https://semver.org/lang/ru/): `MAJOR.MINOR.PATCH`,
где PATCH — исправления, MINOR — новая функциональность без слома
совместимости, MAJOR — несовместимые изменения.

## [3.2.6] — 2026-09-21

### Removed
- Баннер обновления в шапке панели управления и системное уведомление
  «OSE Обновление»: при установке они только мелькали перед перезапуском.
  Обновление по-прежнему ставится из меню кнопки «Обновить» в шапке («Позже» /
  «Обновить»), а итог ручной проверки виден в «Настройки → Приложение». Заодно
  убран ключ `settings.updateInstall` — он был нужен только баннеру.

### Fixed
- По тегу больше не выходит несколько черновиков релиза: публиковал каждый job
  матрицы (`electron-builder --publish`), поэтому на v3.2.5 GitHub получил три
  черновика с одним тегом — в каждом ассеты только своей платформы, а для
  автообновления `latest*.yml` оставались разложены по разным релизам. Теперь
  сборка ничего не публикует (`--publish never`), а единственная задача
  складывает установщики всех платформ в один черновик; повторный запуск
  обновляет его, а не создаёт второй. Что публикация не размножится по
  платформам, проверяет `ci-config`.

## [3.2.5] — 2026-09-21

### Fixed
- Панель «Отладка» прокручивается только в секции логов: раньше скроллилась вся
  панель, поэтому кнопки тестов и заголовок «Логи» уезжали вверх при каждой новой
  строке. Разметка та же — прокрутка переехала с `.debug-panel__body` на список
  логов, а сама панель стала flex-колонкой, где список забирает остаток высоты.

## [3.2.4] — 2026-09-16

### Added
- У вывесок-знаков появился выключатель «Движение» в настройках виджета: Grim HEX
  и Café Musain, знак Nuclear, голограмма Cobra Mk II, эмблема Elite и сфера
  Material You (`grimhex`, `musain`, `nuclear`, `cobra`, `elite-sign`, `md3-orb`).
  С выключенным они стоят на месте — ни покачивания, ни поворота, ни вращения, —
  а неоновая анимация продолжает играть: дыхание яркости, мерцание и глитч по
  сообщению в чате остаются. Включён по умолчанию, так что без правок ничего не
  меняется; у печати TESO и пиксель-куба переключателя нет.

### Changed
- У 3D-алертов Star Citizen, Cobra Mk II и TESO убран наклон карточки: они
  стояли под углом (`perspective(1400px) rotateY(-6deg) rotateX(1deg)`), пока
  остальные панели этих тем — прямо. В редакторе наклон и раньше гасился
  (`#canvas.is-editing .widget-instance`), так что видно это было только в эфире;
  теперь виджет ведёт себя как 2D-алерт, не меняя ни размеров, ни оформления.

### Fixed
- Журнал в панели «Отладка» больше не выдёргивает вниз: каждая новая строка
  безусловно прокручивала список к концу, а протокольные кадры DonationAlerts (они
  идут именно в эту панель) сыплются часто — читать выше было невозможно. Теперь
  панель следует за новыми строками только пока читатель внизу, а при открытии
  показывает свежие — так же, как терминал и панель «DA».

## [3.2.2] — 2026-09-16

### Added
- Шрифты тем больше не зависят от того, что установлено в системе: 11 семейств
  (Manrope, JetBrains Mono, Orbitron, Rajdhani, PT Sans Caption, IBM Plex Mono,
  Cinzel, Montserrat, Roboto, Roboto Condensed, Roboto Mono) вшиты в приложение
  (`assets/fonts/`; начертания 400 и 700, только Latin и Cyrillic) и
  подключаются из `shared/fonts.css`. Раньше на машине без нужного шрифта тема
  молча подменялась системным Segoe UI и выглядела иначе, чем у автора темы, —
  теперь вид одинаков везде. Кириллицы нет у Orbitron, Rajdhani и Cinzel: это
  свойство самих шрифтов, русский текст в этих темах по-прежнему берёт системный
  шрифт. Рядом с каждым набором — текст лицензии (SIL OFL). За тем, чтобы шрифт
  не выпал из сборки, следят `packaging`-тесты: файлы из `url()` в CSS
  проверяются наравне со ссылками страниц, а семейства тем — на совпадение с
  объявленными (и наоборот: вшитый шрифт, который никто не использует, — ошибка).

### Changed
- Публикация релиза теперь сама просит сайт приложения пересобраться: новый
  workflow `notify-site.yml` шлёт `repository_dispatch` в репозиторий
  `ose-website`, поэтому страница с версией и ссылками на установщики
  обновляется сразу после «Publish», а не к следующей выкладке сайта. Нужен
  секрет `SITE_DISPATCH_TOKEN` — PAT с правом Contents: Read and write в
  репозитории сайта; без него шаг падает с понятным сообщением, а сайт
  пересобирается по своему расписанию. Что тип события и адрес не разойдутся,
  проверяет `ci-config`.

## [3.2.1] — 2026-09-16

### Fixed
- По тегу запускались **два** релизных workflow — старый «Build and Release» и
  новый «Release» — и оба собирали установщики и заливали их в один черновик
  релиза: сборка шла наперегонки, а красным становился тот, кто дошёл вторым.
  Из-за этого казалось, что релиз не собирается, — хотя установщики 3.2.0 были
  собраны и лежат в черновике. Остался один workflow: с проверкой версии против
  тега, линтом и тестами перед сборкой; набор платформ не изменился — Windows,
  Linux и macOS (сборки не подписаны). Что дубль не вернётся, проверяет
  `ci-config`.
- Релизный workflow падал на публикации: `npm run dist:win -- --publish always`
  не работает — npm считает `--publish` своим ключом и не передаёт его скрипту,
  поэтому electron-builder получал «--win always» и отвечал «Unknown target:
  always». Теперь цель и публикация передаются сборщику флагами напрямую, а
  локальные `npm run dist:win` / `dist:linux` остались для сборки без публикации.
- Бюджет времени записи мерит код, а не диск CI-раннера. Порог на максимум одной
  записи падал на самом первом сбросе (355 мс против 250 при локальных единицах
  миллисекунд): каталог холодный, файл держит антивирус, неудачный `rename`
  повторяется с задержкой. Теперь смотрится средняя по нескольким «тёплым»
  записям — регрессия видна, а окружение больше не блокирует релиз.

## [3.2.0] — 2026-09-16

### Added
- Ключи приложения видны в панели DonationAlerts: Client ID (значением) и Client
  Secret («заполнен» или «не заполнен», без самого секрета). Это первые две вещи,
  которые надо сверить с кабинетом, когда сервис отвечает `invalid_client`, — и
  видно их теперь без неудачной попытки подключения.
- Панель DonationAlerts (кнопка «DA» в шапке панели управления):
  боковая панель рядом с «Логами» и «Очередью» с ответом на вопрос «почему донаты
  не приходят». Видно состояние подключения и здоровья токена (получен ли,
  обновляется ли автоматически, до какого срока действителен, какой аккаунт),
  рядом — быстрые действия в эфире: переподключить, показать тестовый донат,
  подтянуть пропущенные, переключить озвучку от сервиса, открыть кабинет
  приложения. Ниже — список последних донатов (кто, сколько, когда, какой текст)
  с кнопкой «Повторить алерт»: тестовые алерты в него не попадают, а список
  обновляется сам при каждом донате и ограничен последними десятью — полная
  история с фильтрами и пагинацией остаётся в панели «История». Рядом — галочка
  «Только этот стрим» и счёт текущего стрима (сколько донатов и на какую сумму).
  Под списком — живой журнал только этого сервиса; он копится с запуска
  приложения даже при закрытой панели, поэтому после сбоя видно, что происходило
  до него, а не пустой экран. Настройки подключения (Client ID/Secret,
  «Подключить») остались на вкладке «Настройки». Общий терминал отвечает за все
  сервисы сразу; здесь те же строки отфильтрованы по DonationAlerts, где они не
  тонут среди остальных.
- Состояние авторизации DonationAlerts в состоянии приложения
  (`donationAlertsAuth`: есть ли токен, можно ли обновить, id аккаунта, срок и
  заполнен ли Client Secret) — без самих секретов: только флаги и метки времени.
  По нему панель и показывает «сервис подключён, но токен просрочен и обновлять
  его нечем» или «секрет не заполнен».
- Команда переподключения сервиса (`CMD_RESTART_INTEGRATION`): перезапускает
  интеграцию, не трогая ни настройки, ни приложение; идёт через те же
  `restart*()`, что и старт, поэтому состояние в интерфейсе обновляется обычным
  путём. Оборванный сокет — самая частая причина «донаты перестали приходить».
- Счёт донатов текущего стрима (`state.addDonationToSession`, события
  `session_stats` и `sessionDonations` в состоянии приложения): сколько донатов
  и на какую сумму пришло за сессию. Виден и в панели DonationAlerts, и на
  Web Remote — оба только показывают то, что посчитал сервер. Считается в
  момент прихода доната, а не разбором истории при отрисовке — поэтому цифра
  всегда свежая и не заставляет панель перечитывать растущую историю. Подтянутые
  с DonationAlerts донаты в счёт не идут: они случились в прошлой сессии. В
  историю и в цель сбора они при этом попадают — цель накопительная, не по
  сессии.
- Сброс счёта стрима по кнопке (`CMD_RESET_SESSION_STATS`): нужно, когда начали
  новый стрим без перезапуска приложения или в счёт попал тестовый донат. Кнопка
  есть и в панели DonationAlerts, и на пульте, обе с подтверждением. Сброс
  касается только цифры на экране: история донатов и цель сбора его не замечают,
  и в подтверждении это сказано прямо, чтобы кнопка не читалась как «удалить».
- Виджет «Счётчик» получил метрики «Донатов за стрим» и «Сумма донатов за стрим»
  (`overlay/widgets/stat-widget.js`). Отдельной обвязки для HUD не потребовалось:
  HUD-окно рисует ту же композицию, что и оверлей, поэтому метрика доступна и
  там, и там. Пока счёт не пришёл ни снимком, ни событием — прочерк, а не
  выдуманный ноль; настоящий ноль показывается как ноль. Превью на канвасе
  редактора берёт живое значение, а не пример, — выбранная метрика на канвасе
  совпадает с эфиром.
- Фильтр истории по нижней границе времени (`since` в запросе к истории): по нему
  панель DonationAlerts показывает только донаты текущего стрима. У стрим-событий
  нет `sessionId` — сессия в приложении считается по времени (так же, как в
  агрегатах сессий), поэтому границу задаёт время начала сессии
  (`sessionStartedAt` в состоянии приложения).
- Флаг `alert_queue.enabled` переключается из панели «Очередь», а не только
  правкой `config.json`: `false` — «простой режим» (алерты уходят клиентам сразу,
  без правил, объединения и паузы). Ожидающие при выключении сбрасываются, а тот
  алерт, что уже в эфире, доигрывает и уходит сам — смена режима не выдёргивает
  картинку из-под зрителя. Сам флаг едет в снимке очереди (`enabled`), поэтому
  и панель, и только что подключившийся клиент видят одно и то же.
- Очередь алертов (`server/alert-queue.js`): порядок показа алертов и паузы
  переехали с страницы OBS на сервер. Раньше очередь жила внутри виджета —
  поэтому панель не знала, что в эфире, перезагрузка страницы OBS молча
  выбрасывала непоказанное, а повлиять на порядок было нельзя. Теперь сервер
  рассылает алерты по одному (длительность + хвост на анимацию ухода), знает,
  что играет и что ждёт, и отдаёт текущий алерт заново, если OBS перезагрузил
  страницу. Правила: не показывать донаты ниже суммы, объединять подряд идущие
  донаты одного зрителя в один алерт с суммой и счётчиком. Всё это настраивается
  в панели («Очередь»), состояние видно на пульте.
- Панель очереди в панели управления (`control/control.html`): что в эфире,
  что ждёт, кнопки «Пропустить», «Пауза» (без срока и на 5/15/30 минут),
  «Продолжить», «Показать сейчас», «Выше», «Убрать», «Очистить очередь»;
  правила (минимальная сумма, объединение и его окно); статистика (пришло,
  показано, пропущено, объединено, отсеяно). Панель рисуется целиком из
  снимка очереди, который приходит событием `alert_queue_update` и в общем
  состоянии (`state.alertQueue`), — ничего не запрашивается отдельно.
- Пауза очереди переживает перезапуск приложения: срок хранится в `config.json`
  (`alert_queue.pause_until`), поэтому «пауза на 30 минут» не снимается
  перезапуском. Пауза без срока намеренно срока не имеет — и после перезапуска
  алерты снова показываются (нельзя по неосторожности остаться без алертов).
- Подтягивание пропущенных донатов (`CMD_RECOVER_DONATIONS`): DonationAlerts
  отдаёт сокетом только живые события, поэтому «что пришло пока приложение было
  выключено» спрашивается разово через REST-список донатов. Новым считается
  донат, id которого нет в истории (id стабилен на стороне сервиса, время —
  нет); подтянутое проходит те же побочные эффекты, что и живое (история с
  `source_id`, цель сбора, «последние события»), и помечается в очереди как
  пропущенное. Запрос только по кнопке: у DonationAlerts лимит 60 запросов в
  минуту, а фоновый опрос в цикле его бы выбрал.
- Сквозные сценарии (`tests/e2e-scenarios.test.js`): сервер поднимается как в
  жизни (через `start()`, но с выключенными интеграциями), к нему подключаются
  живые клиенты в ролях control/overlay/chat, и проверяется вся цепочка целиком,
  а не звенья по отдельности: команда панели → рассылка оверлею → запись в
  `local-db.json`; тестовый алерт; сообщение чата из сети ложится в историю с
  привязкой к сессии, а тестовое — нет; повтор события из истории; микрокадры
  уходят только роли overlay и байт-в-байт; переподключившийся оверлей получает
  актуальную раскладку; `stop()` закрывает сессию и шину.
- Бюджеты производительности (`tests/budgets.test.js`): размер снапшота,
  который уходит каждому клиенту; размеры файлов состояния; время записи (берётся
  из телеметрии самого стора); время старта; пачка команд; выборка из истории;
  вещание нескольким клиентам; доступность телеметрии наружу. Пороги с запасом
  на порядок — это забор против регрессий, а не бенчмарк.
- Код доступа для клиентов из локальной сети: панель, оверлей в OBS, HUD и
  редакторы работают с этой машины как и раньше, а всё сетевое (Web Remote на
  телефоне, сторонние скрипты) подключается только с кодом (`?token=…` или
  заголовок `x-ose-token`). Раньше порт слушал все интерфейсы без какой-либо
  проверки, то есть переключать сцены и рассылать алерты мог любой в той же
  Wi-Fi-сети. Код создаётся при первом запуске, лежит в `config.json` и входит в
  адрес пульта; в «Настройки → Доступ из сети» его можно скопировать вместе с
  адресом или заменить новым (старый сразу перестаёт работать, сетевые клиенты
  отключаются). Пустой или чужой код доступа не пускает никого, сравнение — с
  постоянным временем.
- Журнал изменяющих команд (`server/audit-log.js`): время, тип, роль клиента,
  признак «из сети» и пара безопасных деталей (идентификаторы виджета/сцены,
  а не содержимое). Полный payload в журнал не попадает — там бывают сообщения
  чата и настройки, а журнал уходит в отчёт для поддержки. В файловый лог
  пишутся только действия из сети и срабатывания ограничителя частоты, чтобы
  локальные команды панели не заливали лог; последние 50 записей видны в отчёте.
- Ограничитель частоты команд на клиента (60 команд в секунду): защита от
  самодеятельного скрипта или зациклившегося пульта, который засыпал бы шину
  сообщениями. Лишние команды отбрасываются, считаются и попадают в журнал.
- `/healthz` показывает числа по доступу из сети: сколько подключений отбито
  без кода, сколько команд отброшено лимитом и сколько всего записей в журнале.
- Ручное восстановление из резервных копий: в «Настройки → Данные и хранилище»
  появился список копий (`config.json.bak.0…2` и `local-db.json.bak.0…2`) с датой,
  размером и кнопкой «Восстановить». Битые копии помечаются и не нажимаются —
  это видно до отката, а не после. Настройки и база откатываются отдельно;
  откат возвращает раскладку, пресеты и сессии, но не историю событий и чата
  (она живёт в append-only файлах и копиями не покрывается).
- Наблюдатель за долгим прогоном (`server/longrun-monitor.js`): раз в 10 минут
  снимается образец — время работы, rss/heap, клиенты WebSocket, число
  переподключений и пик лага event loop; кольцевой буфер хранит четыре часа
  истории. Из образцов считается скорость роста памяти; строка `[longrun]` в лог
  пишется только когда есть на что смотреть (рост памяти или всплеск
  переподключений). В `/healthz` уходит сводка (при устойчивом росте ≥150 МБ/ч
  он попадает в `problems`), а в отчёт для поддержки — таблица всех образцов.
- Счётчик переподключений интеграций (`state.runtimeStats()`): переход
  «не connecting → connecting» считается один раз, поэтому шторм обрывов виден
  числом, а не только строками в логе.
- Диагностика состояния: `GET /healthz` отдаёт короткий JSON о том, что
  происходит (жив ли сервер, клиенты WebSocket по ролям, статусы интеграций,
  размеры и счётчики хранилища, телеметрия записи, лаг event loop) и список
  проблем; путей к файлам и секретов там нет, поэтому ответ можно смотреть
  мониторингом. `GET /support-bundle` отдаёт полный отчёт для поддержки, но
  **только локальным запросам** — из локальной сети его не скачать.
- Отчёт для поддержки собирается также кнопкой «Сохранить отчёт» в
  «Настройки → Данные и хранилище»: окружение (версии, платформа, память),
  состояние, телеметрия записи, следы восстановлений и карантина, список файлов
  данных, отчёты о падениях, сводка настроек без секретов и хвост лога.
  Маскировка двухслойная: настройки собираются по явному списку полей, а по
  готовому отчёту ещё проходится чистка — ключи вида `*token*`/`*secret*`/
  `*password*` и значения `enc:…`, `?token=…`, `Bearer …` в текст не попадают,
  домашний каталог заменяется на `~`.
- Целостность файлов состояния: битый `config.json` больше не мешает запуску
  (раньше парсинг падал без обработки ошибок, и приложение просто не
  открывалось), а битый `local-db.json` больше не отдаёт `{}` — такой ответ
  следующая же мутация записывала поверх целых данных. Теперь испорченный файл
  уходит в карантин (`<файл>.corrupt-<дата-время>`), состояние поднимается из
  последнего целого бэкапа, а если поднимать нечего — `config.json` собирается
  из шаблона поставки, БД — из значений по умолчанию. Случай порчи виден в
  консоли, в `logs/recovery-<дата>.log` и в диалоге при старте.
- Ротация бэкапов снапшотов в `AsyncAtomicStore`: последний успешно записанный
  снапшот периодически (раз в 5 минут) копируется в `<файл>.bak.0`, предыдущие
  сдвигаются в `.bak.1`/`.bak.2`. Атомарная запись защищает от сбоя во время
  записи, но не от порчи уже лежащего файла — теперь есть и от неё.
- Глобальные обработчики фатальных ошибок (`server/crash-guard.js`, подключены в
  main.js и в режиме `server:only`): непойманная ошибка пишет отчёт
  `logs/crash-<дата>.log` (платформа, версии Node/Electron, память, стек),
  сбрасывает состояние на диск, показывает диалог с путём к отчёту и только
  потом завершает процесс. Непойманные обещания (почти всегда — обрывы сети)
  логируются, но не прерывают эфир; строгий режим — `OSE_STRICT_REJECTIONS=1`,
  отладка непойманных ошибок без выхода — `OSE_KEEP_RUNNING_ON_UNCAUGHT=1`.
- Гейты поставки и релиза в тестах: цели `loadFile`/`loadURL` обязаны
  существовать и попадать в `build.files` (та ошибка, из-за которой окна
  редакторов однажды не доехали до собранного приложения), данные пользователя,
  бэкапы, карантин, логи и медиа должны быть исключены из дистрибутива, словари
  ru/en — совпадать по ключам и подстановкам `{{…}}`, а версия `CHANGELOG.md` —
  совпадать с `package.json` и не повторяться.
- `config/logs/**` и `config/media/**` исключены из сборки: логи, отчёты о
  падении и медиа пользователя не должны попадать в дистрибутив.

### Changed
- Внимание, DonationAlerts: в набор запрашиваемых прав добавлен
  `oauth-donation-index` — он нужен, чтобы подтягивать пропущенные донаты.
  Токены, выданные раньше, нового права не получат: чтобы кнопка «Подтянуть
  пропущенные» заработала, приложение в кабинете DonationAlerts нужно удалить и
  подключить заново. Без этого всё остальное работает как раньше, а кнопка
  честно сообщает, что доступ к списку донатов не выдан.
- Алерты в эфир теперь отдаёт очередь, а не прямой `broadcast` из обработчика
  шины. Изменение намеренно не трогает побочные эффекты: история, цель сбора и
  «последние события» по-прежнему обновляются в момент прихода доната, а не
  показа — донат случился тогда, когда случился, а очередь управляет только
  картинкой. Правило минимальной суммы прячет показ, но не сам донат: он
  попадает и в историю, и в цель сбора.
- Алерты колеса (`wheel_start`/`wheel_winner`) идут мимо очереди: их показ
  привязан к сцене розыгрыша, которую прячет `scheduleWheelHide` по своему
  таймеру, и задержка карточки победителя за чужими алертами была бы
  неправильной. Заодно они не участвуют в объединении.
- Сравнение кода доступа вынесено в `server/access-control.js` вместе с
  правилами доступа и ограничителем частоты: решения «пустить или нет» и
  «принять команду или отбросить» — чистые функции, и они покрыты тестами по
  вариантам (локальный клиент, сетевой без кода, сетевой с кодом, чужой
  источник), а не только через живые сокеты.
- Телеметрия записи (`[atomic-write] …`) показывает число созданных бэкапов за
  интервал.
- `npm run server:only` поднимается под тем же стражем ошибок, что и Electron-
  режим: старт (чтение конфига, привязка порта) — самое частое место падений.
- Журнал DonationAlerts показывает только то, что важно в эфире: смену состояния,
  донаты и обновления цели, ошибки и повторы. Шаги протокола (какой кадр ушёл,
  что ответил Centrifugo, «сырой» кадр доната) переехали в панель «Отладка» и в
  файл журнала: раньше они вытесняли из панели события сервиса, а служебный кадр
  подписки выглядел в ней как полученный донат без доната.

- Попытки подключения к сервису оставляют след в журнале приложения: и когда

  запроса. В строке видно, какой `client_id` уходил, длина секрета (не сам

  только на странице в браузере: вкладку закрыли — и разбирать «почему

- Что приложение прочитало с диска, видно в журнале при запуске (`config loaded`):
  путь к `config.json`, число секций, канал Twitch, `client_id` DonationAlerts,
  состояние секрета (пусто / зашифрован / открытый текст) и есть ли код доступа
  из сети. Без этой строки «настройки сбрасываются при перезапуске» неотличимо

### Fixed
- Прогон тестов больше не затирает рабочий `config.json`. Набор про Колесо
  Фортуны (`tests/giveaway.test.js`) создавал состояние без изоляции каталога
  данных, а конструктор состояния при создании кода доступа из сети писал конфиг
  на диск — то есть `npm test` подменял настройки разработчика фикстурой теста:
  пустой канал, сброшенные ключи и новый адрес пульта на каждый прогон. Наружу
  это выглядело как «настройки не сохраняются, при перезапуске дефолтные». Теперь
  тест пишет во временный каталог, а конфиг, переданный конструктору снаружи
  (тест, импорт настроек), на диск не сохраняется вовсе: это не тот конфиг,
  который лежит в `config.json`.
- Нерасшифрованный секрет больше не уходит в сервис вместо секрета. Если
  сохранённый Client Secret прочитать нельзя (конфиг перенесён с другой машины,
  сменился пользователь ОС, недоступно системное хранилище), то раньше наружу
  отправлялась сама строка `enc:…` — DonationAlerts отвечал невнятным
  `invalid_client`, а ключ в настройках выглядел заполненным, поэтому искать
  причину было нечем. Теперь такое значение считается отсутствующим: и обмен
  кода, и обновление токена говорят об этом прямо, при старте показывается, какой
  именно секрет надо ввести заново, а панель DonationAlerts третьим состоянием
  сообщает «сохранённый не читается — вставьте заново» вместо «не заполнен».
  Причины сбоя («не удалось расшифровать» и «хранилище недоступно») перестали
  быть неразличимыми — раньше они обе выглядели как пустая строка.
- Если Electron работает, а системное хранилище секретов недоступно, факт
  сохранения ключей без шифрования попадает в журнал одной строкой: молчаливая
  запись секретов открытым текстом — не то, о чём пользователь должен узнавать
  сам.
- Из вывода убрано единственное чужое предупреждение об устаревшем модуле:
  Node помечает встроенный `punycode` (DEP0040). Наш код его не требует — искать
  причину среди зависимостей бессмысленно: require из `node_modules` Node не
  предупреждает вовсе (проверено), значит источник — код вне node_modules, то
  есть сам Electron. Глушится ровно этот код, а не выключаются предупреждения
  целиком: молчание спрятало бы и настоящие. Фильтр стоит первой строкой
  `main.js` — до `require("electron")`, — поэтому ловит и то, что порождают
  вызовы Electron из нашего кода. Если он всё-таки появится снова, место укажет
  сам Node: `electron --trace-deprecation .`
- Страница подключения объясняет ошибку словами, а не показывает сырой JSON.
  Раньше при провале обмена кода на токен в браузере появлялось ровно то, что
  ответил сервис: `{"error":"invalid_client","error_description":"Client
  authentication failed","message":"Client authentication failed"}` — без единого
  слова о том, что делать. Теперь известные случаи (`invalid_client`,
  `invalid_grant`, несовпадение `redirect_uri`) переведены в действия, а под ними
  показано, что именно ушло: `client_id`, длина секрета (не сам секрет),
  `redirect_uri` и ответ сервиса как есть.
- Пустые Client ID/Secret больше не приводят к загадочному `invalid_client`:
  и обмен кода, и обновление токена проверяют ключи сами и говорят прямо, чего
  не хватает (и что это надо вписать в настройки). Раньше запрос всё равно
  уходил в сеть, а ответ сервиса ничего не объяснял.
- Обновление токена логирует, что именно отправило: статус, `grant_type`,
  `client_id`, длину секрета (не секрет) и `redirect_uri`. Раньше в ответе
  сервиса не было ни одного нашего поля, и разбирать «почему перестало
  обновляться» приходилось наугад.
- Пустой Client Secret больше не стирает сохранённый: панель принципиально не
  отдаёт секрет обратно в поле (это секрет), поэтому при каждом открытии поле
  пустое — и раньше одно нажатие «Подключить» обнуляло рабочие ключи. Дальше
  обмен токена получал пустой `client_secret`, и сервис отвечал внятным только
  для него `invalid_client` («Client authentication failed»), а пользователь
  видел «перестало подключаться» без единой подсказки почему. Теперь пустое
  значение означает «не менять» (новое значение по-прежнему заменяет старое), а
  рядом с полем секрета есть подсказка. Касается Twitch, DonationAlerts и
  YouTube — у всех трёх была одна и та же ловушка.
- Отклонённые ключи приложения (`invalid_client`) больше не крутят бесконечные
  переподключения к DonationAlerts каждые 15 секунд: без правки Client ID/Secret
  повторы ничего не изменят, а только засоряют журнал. В журнал сервиса теперь
  пишется прямая подсказка, а интеграция поднимется заново сама, когда ключи
  поправят и нажмут «Подключить DonationAlerts».
- Конфиг без раздела `goal`/`topDonation` больше не роняет обработчик алертов:
  разделы нормализуются при загрузке, как остальные настройки. Нашли это сквозные
  тесты — на урезанном конфиге первый же донат приводил к `TypeError` в
  `addToGoal`, после чего переставали работать и остальные команды.
- Слайдеры в «Настройках» снова цвета акцента темы (`accent-color`):
  раньше браузер рисовал их системным синим.
- `tests/perf-monitor.test.js` больше не падает по таймингам: величина лага
  считается гистограммой Node по своему таймеру, и замер мог не попасть внутрь
  залипания. Теперь проверяется контракт модуля (пишет строку при достигнутом
  пороге), а не значение лага.

  показывает её сразу.
- Защита от нечитаемых сочетаний в движке тем: производные акценты и
  автоматические `--md-on-surface`/`--md-on-surface-variant` проверяются по
  контрасту WCAG относительно фактического фона (включая вручную заданный
  `background`) и при необходимости подстраивают светлоту. Раньше светлый фон
  при тёмной схеме оставлял светло-серый текст — «ничего не видно».

- Уборка осиротевших temp-файлов (`sweepStaleTempFiles`): temp от процессов,
  убитых ровно между записью и rename, удаляются при создании стора или истории.
  Файлы младше минуты не трогаются, чтобы не задеть живой процесс.

### Changed
- История стрим-событий вынесена из `local-db.json` в отдельный append-only
  файл `local-db.jsonl` (JSON Lines): каждое событие дописывается одной
  строкой, а не перезаписывает всю базу. Старые события из `local-db.json`
  переносятся автоматически при первом запуске. Повреждённые строки при
  чтении пропускаются, поэтому сбой во время записи теряет максимум последнюю
  запись. Хранятся только последние 20 000 событий: файл периодически
  уплотняется (атомарно) с гистерезисом, так что на диске он не растёт
  бесконечно и не переписывается на каждое событие. Лимит можно изменить
  в настройках.
- Колесо Фортуны убрано с основного оверлея — оно существует только в своей
  сцене (`overlay/wheel-scene.html`). Раньше разметка и логика барабана
  дублировались в `overlay/overlay.html`/`overlay.js` и грузились в основной
  оверлей, даже когда сцена колеса не используется.
- Виджет «Участники розыгрыша» удалён из каталога и основного оверлея: список
  участников теперь живёт только на сцене колеса (`wheel-scene.html`), где
  настраивается в панели «Колесо». Из сохранённых раскладок такой виджет
  вычищается при загрузке.
- Поиск по истории (чат/события) больше не разбирает JSON всех строк: файл
  читается один раз, а `JSON.parse` вызывается только для строк, где искомая
  подстрока есть в сыром виде (с учётом JSON-экранирования). На 10 000 строк
  поиск ускорился в ~2.5–4 раза (43.7 → 17.9 мс без совпадений, 28.3 → 6.5 мс
  при одном совпадении).
- Справка и README: пункт про «Завершать работу источника, когда он не
  отображается» выделен и объяснён — без него Chromium внутри OBS может не
  выставить `document.hidden` для неактивной сцены, и пауза rAF-циклов
  3D-виджетов не сработает.

### Fixed
- Колесо Фортуны скрывается автоматически по завершении розыгрыша: после
  показа победителя (обычный режим или финальный победитель в режиме на

## [1.7.0] — 2026-08-09

### Added
- Отдельное окно **«Чат»** — читаемый лог сообщений Twitch-чата (без
  прозрачных карточек оверлея), чтобы следить за чатом во время стрима, не

  HTML / CSS / JS с живым превью (обновляется на лету при вводе) и кнопкой
  «Сохранить». Открывается кнопкой «Редактировать код» в панели свойств,
  когда у виджета выбран режим «Свой HTML».

### Fixed
- **JS в «Своём виджете» теперь реально выполняется.** Раньше произвольный
  HTML вставлялся через `innerHTML`, из-за чего вложенные `<script>` тихо
  не срабатывали (стандартное поведение браузеров). Рендер переведён на
  `<iframe>` с полноценным HTML-документом (свой `<style>` и `<script>`),
  так что таймеры, анимации и любой код в виджете работают по-настоящему —
  и в превью редактора, и на настоящем оверлее.
