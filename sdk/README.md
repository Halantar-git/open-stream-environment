# SDK пакетов OSE

Набор для разработки виджетов и тем, которые OSE подхватывает из папки — без
пересборки приложения и без публикации в реестре.

Что внутри:

| Файл | Зачем |
|---|---|
| `bin/ose-plugin.mjs` | единая команда `npx ose-plugin create` / `check` / `pack` |
| `create.mjs` | создаёт рабочий пакет виджета или темы |
| `validate.mjs` | проверяет пакет по тем же правилам, что `src-tauri/src/plugins.rs` |
| `pack.mjs` | собирает пакет в zip для установки из панели |
| `index.d.ts` | типы `window.OSE`, `BaseWidget`, событий и манифестов |
| `schema/` | JSON-схемы `widget.json` и `theme.json` для редактора |
| `templates/` | то, из чего `create` собирает пакет |

Подробный формат пакета и таблица API — в
[`docs/plugin-api.md`](../docs/plugin-api.md). Здесь — как этим пользоваться.

## Быстрый старт

Пакет SDK есть в npm как `ose-plugin` — репозиторий OSE клонировать не
обязательно. Нужен Node 18+.

```sh
# виджет ./hello
npx ose-plugin create hello

# тема
npx ose-plugin create plain --theme --name "Plain"

# проверить готовый пакет или весь каталог
npx ose-plugin check hello
npx ose-plugin check config/plugins

# собрать архив для установки из панели
npx ose-plugin pack hello
```

В репозитории OSE то же самое без сети: `node sdk/create.mjs`,
`node sdk/validate.mjs` и `node sdk/pack.mjs`.

### Команды

`ose-plugin create <id>`:

| Параметр | Что делает |
|---|---|
| `--theme` | создаёт пакет темы вместо виджета |
| `--name «…»` | имя карточки (по умолчанию — id) |
| `--description «…»` | описание карточки |
| `--dir <каталог>` | куда положить папку; по умолчанию текущая |
| `--force` | писать в непустую папку |

`ose-plugin check [путь]`:

| Параметр | Что делает |
|---|---|
| `<путь>` | папка пакета или каталог пакетов; по умолчанию `.` |
| `--json` | вывод в JSON для скриптов и CI |

Код возврата `1` — есть ошибки; предупреждения его не меняют.

`ose-plugin pack <папка>`:

| Параметр | Что делает |
|---|---|
| `<папка>` | папка готового пакета; сначала прогоняется та же проверка, что у `check` |
| `--out <файл>` | куда положить архив; по умолчанию `<id>.zip` в текущем каталоге |

В архив не попадают `node_modules`, `.git` и служебные файлы Finder и Windows.
Манифест лежит в корне архива.

Пакет сразу рабочий: скопируйте папку в каталог пакетов или поставьте архив
через «Настройки → Пакеты» → «Установить из ZIP», обновите страницу панели
(или источник в OBS) и добавьте карточку из библиотеки.

- разработка (`npm run tauri:dev`) — `config/plugins/<id>/`;
- установленное приложение — каталог данных `com.openstreamenvironment.app`
  (Windows: `%APPDATA%\com.openstreamenvironment.app\plugins\`).

Манифесты перечитываются, когда панель или оверлей запрашивают `/api/plugins`
при загрузке страницы. После установки или правки `widget.json`/`theme.json`
перезапуск приложения не нужен: панель при возврате фокуса заметит новый список
и сама перезагрузит страницу; источник в OBS обновите вручную — оверлей не
трогаем, чтобы не рвать эфир. Код и CSS сервер отдаёт с диска, поэтому правки
видны сразу после обновления.

## Виджет

```
hello/
  widget.json   — манифест: id, настройки, геометрия по умолчанию
  widget.js     — класс виджета, регистрируется через OSE.defineWidget
  widget.css    — стили, ограниченные data-type="plugin:hello"
  README.md
```

```js
(function () {
  const OSE = window.OSE;
  if (!OSE) return;

  class HelloWidget extends OSE.BaseWidget {
    render() {
      if (!this.element) return;
      this.element.textContent = String(this.config.text || "Привет");
    }
  }

  OSE.defineWidget("hello", HelloWidget);
})();
```

`OSE.BaseWidget` даёт:

| Что | Зачем |
|---|---|
| `this.config` | значения настроек из инспектора (умолчания — из `settings`) |
| `this.geometry` | `x`, `y`, `w`, `h`, `z`, `visible` в процентах холста |
| `this.element` | `div` (`canvas` у `renderType: "canvas"`), в котором рисует виджет |
| `this.canvas`, `this.ctx`, `this.gl` | холст и контексты, если они нужны |
| `onMount()` / `render()` / `onUpdate(prev, next)` / `onUnmount()` | жизненный цикл |
| `this.subscribe(type, handler)` | подписка на шину; снимается при удалении |
| `this.later(fn, ms)` / `this.every(fn, ms)` | таймеры, которые снимаются при удалении |
| `this.on(target, type, fn)` | DOM-слушатель, который снимается при удалении |
| `this.startRenderLoop(fps)` / `this.stopRenderLoop()` | анимация на canvas |
| `this.context.readCssVar(name)` | токен темы (`--md-primary` и т. п.) |
| `this.context.t(key)`, `this.context.escapeHtml(text)` | локализация и экранирование |

Плюс у `window.OSE`: `asset(id, файл)` — адрес файла пакета, `cssVar(name)` —
цвет темы для canvas, `t(key)`, `EVENT_TYPES`, `onWidget(listener)`, `load()`.

### Манифест

| Поле | Обязательное | Что задаёт |
|---|---|---|
| `apiVersion` | да | версия контракта, сейчас `1` |
| `kind` | да | `"widget"` |
| `id` | да | имя папки: латиница в нижнем регистре, цифры, `.`, `-`, `_` |
| `name` | да | имя карточки в библиотеке |
| `entry` | да | `.js`-файл внутри пакета |
| `description` | нет | описание карточки |
| `version`, `author` | нет | метаданные в списке пакетов |
| `styles` | нет | массив `.css`-файлов внутри пакета |
| `icon` | нет | ключ из `shared/icons.js`; неизвестный заменяется на `widgetCustom` |
| `defaultGeometry` | нет | `x`, `y`, `w`, `h` в процентах холста; по умолчанию `10, 10, 24, 12` |
| `minW`, `minH` | нет | минимум при растягивании, по умолчанию `5`, допустимо `0.5–100` |
| `settings` | нет | схема настроек для инспектора |
| `$schema` | нет | ссылка на JSON-схему для редактора; приложение игнорирует |

Геометрия клампится: `w` и `h` — до 100, `x` и `y` — так, чтобы виджет не
вышел за холст.

### Настройки

Инспектор рисует поля сам по схеме `settings` — вручную ничего верстать не
нужно. Типы: `string`, `text`, `number`, `range`, `color`, `boolean`, `select`.
У `select` значение по умолчанию должно быть из `options`; иначе приложение
молча возьмёт первый вариант, а `validate.mjs` об этом предупредит.

```json
"settings": {
  "title": { "type": "string", "label": "Заголовок", "default": "Эфир" },
  "size": { "type": "range", "label": "Размер", "min": 8, "max": 72, "step": 1, "default": 24 },
  "mode": {
    "type": "select",
    "label": "Режим",
    "default": "short",
    "options": [
      { "value": "short", "label": "Коротко" },
      { "value": "full", "label": "Подробно" }
    ]
  }
}
```

| Поле | Что задаёт |
|---|---|
| `type` | `string`, `text`, `number`, `range`, `color`, `boolean`, `select` |
| `label` | подпись поля в инспекторе |
| `default` | значение по умолчанию; попадает в `this.config` |
| `min`, `max`, `step` | границы и шаг для `number` и `range` |
| `placeholder` | подсказка в пустом поле |
| `options` | варианты `select`: строка или `{ "value", "label" }` |

Имя настройки — латиница, цифры, `_` и `-`, до 40 символов: оно становится
ключом в `this.config` и id поля в инспекторе.

### События

Подписка идёт по имени из `OSE.EVENT_TYPES` — это те же кадры, что летят в
оверлей:

```js
this.subscribe(OSE.EVENT_TYPES.ALERT, (alert) => {
  this.element.textContent = `${alert.kind}: ${alert.user}`;
});
```

Самые нужные события и их нагрузка:

| Событие | Что в нагрузке |
|---|---|
| `ALERT` | `kind`, `user`, `amount?`, `currency?`, `message?`, `tier?`, `count?` |
| `CHAT_MESSAGE` | `user`, `message`, `color?`, `badges?` |
| `RECENT_EVENT` | запись из «последних событий» |
| `GOAL_UPDATE` | `current`, `target`, `title?`, `currency?` |
| `STAT_UPDATE` | `followerCount`, `subscriberCount` |
| `SESSION_STATS` | `count`, `amount`, `currency` |
| `THEME_UPDATE` | `activeThemeId`, `enable3d`, `tokens` |

Полный список и точные поля — `shared/events.js` и `docs/api.md`; типы ключевых
событий — в `index.d.ts`.

## Тема

```
plain/
  theme.json   — манифест и токены
  theme.css    — необязательные правила под [data-theme="plugin:plain"]
  README.md
```

| Поле | Обязательное | Что задаёт |
|---|---|---|
| `apiVersion` | да | версия контракта, сейчас `1` |
| `kind` | да | `"theme"` |
| `id` | да | имя папки; тема появляется как `plugin:<id>` |
| `name` | да | имя в «Настройки → Оформление» |
| `tokens` | да | минимум один токен `--…` со строковым значением |
| `css` | нет | `.css`-файл внутри пакета |
| `description`, `version`, `author` | нет | описание и метаданные |

Токены: цвета `--md-*`, шрифты `--font-display`/`--font-body`/`--font-mono`,
панели `--panel-*`. Незаданные токены остаются от предыдущего оформления,
поэтому берите полный набор — как в заготовке `create` — иначе половина виджетов
останется в старых цветах.

Тема появляется в «Настройки → Оформление» как `plugin:<id>` и применяется на
оверлее, сценах и заставке. Править её из панели нельзя — источник правды в
пакете. CSS пишите под своим `data-theme`, иначе правила протекут в другие
темы и в панель управления.

Шрифт попадает в эфир — только свободная лицензия, разрешающая коммерческое
использование (SIL OFL и подобные), текст лицензии рядом с файлом.

## Типы

`index.d.ts` — обычный TypeScript-файл глобальных деклараций, компилировать
ничего не нужно. Добавьте в начало своего JS:

```js
/// <reference path="node_modules/ose-plugin/index.d.ts" />
// @ts-check
```

В репозитории OSE — вместо этого `../sdk/index.d.ts`. Редактор начнёт
подсказывать `this.config`, события и хуки. Если пакет лежит вне проекта,
скопируйте `index.d.ts` к себе или укажите путь до него.

Манифесты типизированы отдельно: `Ose.WidgetManifest`, `Ose.ThemeManifest`.
Для проверки в редакторе добавьте в `widget.json` ссылку на схему:

```json
"$schema": "../../sdk/schema/widget.schema.json"
```

(путь считайте от расположения пакета; приложение поле `$schema` игнорирует.)

## Проверка

`validate.mjs` повторяет правила загрузчика: id совпадает с папкой, `entry` и
`styles` существуют и лежат внутри пакета, настройки известных типов, у темы
есть токены с `--`. Предупреждения не мешают установке — приложение такой
пакет примет, но обычно это опечатка.

Что ловится:

- имя папки не по правилам или `id` не совпадает с папкой;
- нет ни одного манифеста или в пакете оба сразу;
- `entry`, `styles` или `css` не существуют, выходят за пакет или не того типа;
- неизвестный `type` настройки, неверные `options`, ключ настройки не по правилам;
- у темы пустые `tokens` или токен без `--`;
- `apiVersion` не равен 1, `kind` не совпадает с файлом, пустой `name`.

Предупреждения — `default` не из `options`, `defaultGeometry` не объект,
`css` не строка: приложение установку не отклонит, но, скорее всего, автор имел
в виду другое.

```sh
npx ose-plugin check <папка>        # один пакет
npx ose-plugin check config/plugins # все пакеты каталога
npx ose-plugin check <папка> --json # для скриптов и CI
```

Код возврата 1 — есть ошибки. В репозитории OSE — `node sdk/validate.mjs` с
теми же аргументами.

## Если пакет не появился

- Обновите страницу панели или источник в OBS: панель замечает новый список
  при возврате фокуса и перезагружается сама; оверлей обновляют вручную.
- Папка должна называться так же, как `id`, и лежать в каталоге пакетов; в ней
  ровно один манифест — `widget.json` **или** `theme.json`.
- Ошибки загрузки пишутся в терминал приложения (`[ose] пакет <id>: …`) и
  возвращаются в `GET /api/plugins` в поле `errors`.
- Правки `widget.js` и `widget.css` подхватываются без перезапуска — обновите
  Browser Source в OBS или переоткройте превью.

## Ограничения

- Код пакета живёт в рамке-песочнице (`iframe` без доступа к странице оверлея),
  но сеть ей доступна — ставить можно только доверенный код.
- 3D-виджет и его тема — два пакета: в одном каталоге один манифест, а тема
  ссылается на тип виджета через `threeDWidgets`.
- Установка — папкой или zip; обновления и подписи — следующий этап.

## Публикация в npm

Пакет `ose-plugin` живёт в `sdk/`. Перед публикацией проверьте состав — в
архив должны попасть `bin`, `templates`, `schema`, `index.d.ts` и `LICENSE`:

```sh
cd sdk
npm pack --dry-run
npm login
npm publish
```

Версию поднимайте в `sdk/package.json` (semver), после — коммит в репозиторий.
Версия SDK не связана с версией приложения: контракт пакетов держится на
`apiVersion: 1`, а не на номере npm-пакета.

Имя пакета и имя команды в `bin` должны совпадать: `npx` первым словом ищет
пакет, поэтому `npx ose-plugin` сработает только у пакета `ose-plugin`. Если на
аккаунте включена 2FA, публикуйте с `--otp=<код>` или automation-токеном —
иначе npm оставит версию в очереди и следующая попытка получит 409.

После публикации проверьте `npx --yes ose-plugin@latest --help`, а старое имя
пакета пометьте `npm deprecate` (или `npm unpublish` в первые 72 часа), чтобы в
поиске не висели два одинаковых SDK.
