# AGENTS.md

Правила для агентов, работающих с этим репозиторием.

## Релиз

**`release.bat` агент запускает сам.** Скрипт спрашивает версию через
`set /p`, поэтому агенту нужно подать её на вход, например
`echo 4.0.1| release.bat`. Версия по умолчанию — patch-инкремент от текущей;
если владелец назвал версию явно, берётся она. Задача агента — довести дерево
до состояния, когда `release.bat` отработает с первой попытки, и затем
запустить его: скрипт сам поднимет версию, закоммитит, запушит `main` и
поставит тег. Коммитить агент может и вручную, по ходу работы.

Что считается «релиз подготовлен»:

- версия поднята в `package.json` и `package-lock.json` (оба поля: верхнее
  `version` и `packages[""].version`) и в `src-tauri/tauri.conf.json` (поле
  `version`) — `release.bat` синхронизирует их сам; заодно агент поднимает
  `src-tauri/Cargo.toml` и `Cargo.lock` (поле `version` корневого пакета) —
  `release.bat` их не трогает, а оттуда берётся версия в приложении и отчётах;
- в `README.md` строка «Текущая версия: **X.Y.Z**.» обновлена;
- в `CHANGELOG.md` секция `## [Unreleased]` стала `## [X.Y.Z] — YYYY-MM-DD`
  (сегодняшняя дата), версия совпадает с `package.json`, повторяющихся версий
  нет — это проверяет `tests/changelog.test.js`;
- `commit.txt` — сообщение релизного коммита (формат прошлых релизов:
  `Релиз vX.Y.Z: краткое описание`, ниже — пункты);
- `discord-update.txt` — заметки для сообщества под версию;
- `npm test`, `npm run lint`, `cargo test --manifest-path src-tauri/Cargo.toml
  --lib` и `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --
  -D warnings` зелёные;
- `git status` не содержит мусора: `release.bat` делает `git add .`, поэтому
  любые лишние файлы уедут в коммит.

Версия по умолчанию — patch-инкремент от текущей; если владелец назвал версию
явно, берётся она.

## Ловушки `release.bat`

- В `discord-update.txt` он заменяет **все** подстроки вида `X.Y.Z` на номер
  версии. Поэтому в заметках нельзя писать точечные числа (IP, версии, порты) —
  иначе `127.0.0.1` превратится в `127.0.0.<версия>`.
- Заголовок `## [X.Y.Z] …` в `CHANGELOG.md` вставляется, только если такого
  заголовка ещё нет; уже созданный агент не трогает, дата остаётся агентской.
- `npm version … --no-git-tag-version` вызывается только если версия в
  `package.json` отличается от введённой, поэтому повторный запуск безопасен.
- Скрипт сам делает коммит, push `main` и тег `vX.Y.Z`, после чего срабатывают
  `release.yml` (проверка «тег = `package.json` = `tauri.conf.json`», линт,
  Rust-гейт, сборка `tauri-action`, черновик релиза) и `notify-site.yml`
  (пересборка сайта; нужен секрет `SITE_DISPATCH_TOKEN`). Публикация релиза
  остаётся ручной.

## Справка

Справка (`control/modules/help-panel.js` и ключи `help.*` в
`shared/locales/ru.json` / `en.json`) — часть интерфейса, а не документация «на
потом». Новая настройка, режим, тумблер, панель или заметное изменение
поведения попадают в неё **в той же работе**, а не отдельной задачей. То же
касается исправления, если оно меняет то, что в справке уже написано.

- Перед коммитом сверь описание с интерфейсом: названия режимов и кнопок — как
  в локалях, диапазоны и умолчания — как в коде. Подпись «Огибающая спектра» в
  справке должна совпадать с той, что видит пользователь.
- Новый пункт — абзац `pN` в подходящей секции; новая группа настроек — секция
  в `SECTIONS`, вставленная по смыслу, а не в конец списка.
- Правишь оба словаря сразу: ключи и подстановки `{{…}}` симметричны
  (`tests/i18n.test.js`).
- Перед релизом пройдись по `CHANGELOG.md`: всё из будущей секции версии либо
  описано, либо сознательно оставлено за кадром (внутреннее, без влияния на
  пользователя). Так справка не отстаёт на несколько версий.
- Фича ещё не устоялась — опиши как есть: устаревшая справка хуже короткой, а
  «обновим потом» не наступает.

## Конвенции проекта

- Русский язык: комментарии, CHANGELOG, README, заметки о релизе.
- Комментарии — человекочитаемые: объясняют **почему** так сделано (причину,
  ограничение, подводный камень), а не пересказывают код. Без служебных пометок
  («сгенерировано ИИ», «сделал агент»), машинного жаргона и отчётов о своих
  действиях.
- Коммиты — человекочитаемые и по делу: одно законченное изменение на коммит,
  заголовок в повелительном наклонении, тело объясняет смысл («зачем»), а не
  перечисляет файлы. Без «wip», «правки по просьбе» и прочего шума.
- Бэкенд — Rust (`src-tauri/`), фронт — JS в системном webview. Node нужен
  только для разработки (Jest, ESLint/Prettier, скрипты данных
  `src-tauri/tools/*.mjs`) и в поставку не входит.
- Словари `shared/locales/ru.json` и `en.json` синхронны по ключам и
  подстановкам `{{…}}`.
- Геометрия виджетов — проценты холста, а сетка редактора — `gridSize` процентов
  от каждой оси; её линии проходят по кратным `gridSize`. Виджет получается
  одновременно ровным по сетке и симметричным относительно центральной линии
  только при **чётном числе клеток** по ширине (при сетке 2% это `w=32`, а не
  `30`): у нечётного числа центр попадает на середину клетки. Не «лечить» это
  сдвигом `x` на полклетки — края сойдут с линий; менять нужно ширину.
- Порядок ключей в `shared/widget-catalog.js` задаёт порядок карточек в колонке
  виджетов. Ключи идут блоками по темам: общие 2D → Orbital/свои → Star
  Citizen (Grim HEX) → Nuclear → Cobra Mk II → TESO → Wardogs → Material You →
  Pixel Perfect → интеграции DonateX. Новый виджет ставится в блок своей темы,
  а не в конец файла; UEC-перевод, доступный в любой теме, живёт в блоке Grim
  HEX сразу после «Цель Grim HEX». После правки каталога — `node
  src-tauri/tools/build-widget-catalog.mjs`.
- Данные dev- и релизной сборки лежат в разных местах: `npm run tauri:dev`
  читает `config/` в корне репозитория, установленная версия —
  `%APPDATA%/com.openstreamenvironment.app/`. Правку раскладки проверять в том
  файле, который читает запущенный экземпляр.
- Шрифты, которые попадают в эфир (оверлей и сцены — всё, что видит зритель),
  — только свободные и разрешённые к коммерческому использованию: в приоритете
  SIL Open Font License, иначе другая бесплатная лицензия без запрета на
  монетизацию. Набор лежит в `assets/fonts/` и подключается через
  `shared/fonts.css`, текст лицензии — рядом с файлами. Шрифт без такого
  разрешения в тему не берём: стрим с донатами — коммерческое использование.
  Правило касается только эфирных шрифтов; набор интерфейса панели управления
  под него не подпадает.
- Тесты фронта — Jest (`npm test`), бэкенда — `cargo test --lib`; линт —
  ESLint + Prettier (`npm run lint`, `npm run format`) и `cargo clippy`.
- Коммиты: агент фиксирует свою работу сам; рабочая ветка — текущая, гейт
  перед коммитом зелёный. Релизный коммит, push `main` и тег ставит
  `release.bat` — его запускает агент, подав версию на вход.
- Данные пользователя (`config.json`, `local-db.json`, `local-db.jsonl`,
  `local-db.chat.jsonl`, `window-state.json`, логи, медиа, temp-файлы) не
  коммитятся и исключены из сборки — это проверяют `packaging`-тесты.
